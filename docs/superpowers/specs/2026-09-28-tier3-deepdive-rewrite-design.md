# Tier 3: rewrite MM_TERRARIUM.md as a current-state reference

**Status:** approved in session 2026-09-28. This is the third and last tier of
the codebase optimization audit: Tier 1 was PR #151, Tier 2 was PRs #152 and
#153.

**Goal:** turn `docs/MM_TERRARIUM.md` from a dated build log (6,190 lines,
420KB) into a current-state reference of about 1,500 to 2,000 lines, and
delete the implementation plans for work that has landed.

Nothing current may be lost in the process, and every inbound reference must
keep working.

## Decisions (made with the user)

1. **History is dropped, not moved.** The new doc explains the reasons
   behind current behavior inline. Build logs, dated status lines,
   superseded approaches and "corrected by measurement" narratives are
   deleted. One line near the top names the last pre-rewrite commit on
   `main`, so the old text stays one command away:
   `git show <sha>:docs/MM_TERRARIUM.md`.
2. **Landed plans are deleted; specs are kept.** Specs hold the design
   reasoning, and the doc links them for "why".
3. **Headings that are cited by name are kept exactly.** Everything under
   "Landed subsystems" is restructured freely. Stale inbound pointers are
   fixed in the same effort.

## Hard constraints (from the dependency inventory)

- **Path and hooks.** The path stays `docs/MM_TERRARIUM.md`. Hooks derive
  it from `mm-meta.yml`, and `mm-require-deepdive.sh` blocks tools until

  `tests/test_diagrams.py` must pass. `docs/diagrams/manifest.json` is not
  changed.
- **Headings kept verbatim:**
  - "What it is, in one picture"
  - "Landed subsystems"
  - "Boundary rules (the load-bearing invariants)", with each rule keeping

- **Links.** The repo is public, so links stay absolute GitHub URLs or

## Target structure

1. **Header.** One paragraph on what the Terrarium is. Then status: what
   is real, and what is missing (pointing at "Not yet built / deferred").
   Then the pre-rewrite SHA pointer.
2. **"What it is, in one picture".** The `light-path` and `player-flow`
   diagrams, plus the Bit, role and flow overview.
3. **Running it** (new). Covers:
   - venv and worktree setup (the `.venv` symlink)
   - running the test suites
   - `terrarium.sh`, `smoke-test.sh` and `harness.run_stack`, with the
     main flags
   - profiles
   - ports
   - logs and `runs/`
   - the arco checkout resolution
4. **"Landed subsystems".** One subsection per package, written as
   reference: purpose, key types and entry points, contracts, and
   gotchas. Packages: `control/`, `devicelink/`, `harness/`, `console/`,
   `uplink/`, `capture/`, `contract_kit/`, `bits/` (each Bit briefly), and
   `www/` with `arcoserver/`. The remaining four diagrams go in their
   matching subsections.
5. **"Boundary rules (the load-bearing invariants)".** Kept, with the
   numbering unchanged.
6. **"Host platform (gotcha)".** Kept, with stale lines trimmed.
7. **"Relationships to other repos".** Kept, with dates removed.
8. **"Not yet built / deferred".** Only the items that are still open.
   Closed items are removed; the dependency inventory lists nine.
9. **"Design docs (in-repo, authoritative)".** Kept. Links to deleted
   plans are replaced with links to the same-named spec.

**Content rules for the new doc:**
- No status phrased as "as of <date>".
- No test-count baselines.
- No strike-throughs.
- No "superseded" notes.
- Every file path mentioned must exist.
- Deleted modules may appear only where a current gotcha needs them to
  make sense.

## Execution

- **Step 1: outline and mapping.** One task writes the new skeleton: all
  kept headings, the six diagram markers in place, and a mapping table
  (old line range to new section). The table marks each old block as
  current, history or deleted-code. It is kept in the plan workspace; it
  is not committed.
- **Step 2: sections.** Each new section is written by its own task from
  its mapped old lines, checking claims against the code.
- **Step 3: finish.** An editing pass makes the whole doc consistent, the
  inbound pointers are fixed, the plans are deleted, and the verification
  above runs.
- **Delivery:** one PR on `claude/tier3-deepdive-rewrite`. The
  mm-documents edits are a separate change.
